# Java Evaluator（Java 面试评估）

## 概览

- **输入**：已填写完成的《<姓名>-面试题与评分表.md》（由 java-interviewer 技能生成，面试官已录入每题候选人回答记录、第 1 题末尾的水平定位勾选）
- **输出**：`<候选人姓名>/<姓名>-评估报告.md`（文件名以求职者姓名开头，如 `林得富-评估报告.md`）
- **定位**：本技能独立于出题技能 `java-interviewer`——java-interviewer 只负责生成评分表，**评估报告统一由本技能生成**。

## 输入处理

- 读取《<姓名>-面试题与评分表.md》中的：候选人关键核验信息、固定 JD 匹配检查、每题「候选人回答记录」区、第 1 题末尾的「水平定位」勾选（初级/中级/高级/资深/专家 + 依据）。
- 语音转写可能不准确：按上下文推断候选人真实意图与表达，不逐字照搬，并在报告中说明「按上下文推断」。
- **候选人回答记录为空 = 面试官未提问**：**直接过滤**——不评估、不列示、不扣分，评估只基于面试官实际提问且有回答的题目。
- 未填写水平定位勾选时（定级题未提问）：按已答题目的回答质量推断建议等级与面试评级，并在报告中注明「水平定位未勾选，按回答质量推断」。
- 评估以评分表回答记录与简历事实为准，**不无中生有**（不编造候选人没说过、简历里没有的内容）。

## 评估步骤

1. 读取每题「候选人回答记录」与第 1 题末尾的「水平定位」勾选结果（工作簿不打分）；**只保留面试官实际提问且有回答的题目**，无回答的题目视为未提问并过滤，不参与评估。
2. 对照「等级评定标准」给出建议等级（**以第 1 题水平定位判定为主、整体回答质量为辅**；水平定位未勾选时按已答题目回答质量推断）。
3. 评估五个维度：Java 基础扎实度、技术广度、深度、实战经验、系统设计与架构能力；并结合固定 JD 匹配度、外包/青岛岗位适配度。
4. 按「等级与评级对应标准」由建议等级映射出**面试评级（A/B/C/D，A 最好、D 最差）**，**保证建议等级与面试评级口径一致**（可因真实性问题在对应档内下调，但不与等级矛盾）。
5. 输出整体评价：强项、短板、综合评语、录用建议（通过/待定/不通过），并说明理由；给出二面重点关注清单（把未问到或回答薄弱的关键项列给项目经理）。
6. 保存为 `<候选人姓名>/<姓名>-评估报告.md`；重名覆盖，保留最新一份。

## 等级评定标准（结合回答质量综合判断）

| 等级 | 典型特征 |
|------|---------|
| 初级 | 掌握 Java 语法与基础 API，能独立完成简单 CRUD 功能；对框架使用有基本了解 |
| 中级 | 2-4 年经验；能独立负责模块开发，理解常用框架原理与数据库优化，能处理常见并发问题 |
| 高级 | 4-7 年经验；能主导核心模块/系统设计，熟悉分布式、缓存、MQ 等中间件并解决线上问题，具备性能调优能力 |
| 资深 | 7 年以上经验；具备架构设计能力，能设计高可用/高并发系统，对技术选型与成本/演进有清晰判断 |
| 专家 | 领域专家；能定义技术规范、主导大型系统架构、解决复杂疑难问题，对行业前沿有深度洞察 |

等级判定以**第 1 题水平定位**为主、整体回答质量为辅；两者不一致时，以回答质量与真实经历信号为准，并在报告中说明差异。**真实经历信号**（具体数字、时间、角色、踩坑过程）优先于背题式回答。

## 面试评级标准（A/B/C/D，A 最好、D 最差）

面试评级是对候选人**整体面试表现**的综合评价，用于快速给用人决策分级，须与「建议等级」「录用建议」强相关：

| 评级 | 总体表现 | 判定要点 | 对应建议等级参考 | 录用建议 |
|---|---|---|---|---|
| **A（优秀）** | 高度匹配岗位，原理与实践俱佳 | 第 1 题水平定位 ≥ 高级；回答质量高、真实经历信号强；五个维度多为强；JD 匹配度高，无明显硬伤 | 高级 / 资深 / 专家 | 推荐（通过），可直接推荐二面/录用 |
| **B（良好）** | 基本胜任，个别短板 | 水平定位 高级/资深边缘或整体达到岗位要求；回答整体良好但有 1-2 个短板；JD 匹配度中高 | 中级偏上 ~ 高级 | 推荐二面（通过/待定） |
| **C（一般）** | 未完全达到岗位要求，需谨慎 | 水平定位 中级~高级之间但未达岗位要求；原理薄弱、真实性存疑或 JD 匹配度中低；存在明显短板 | 中级 ~ 中级偏上 | 待定，谨慎（二面重点验证或按低价录用） |
| **D（较差）** | 明显不匹配，不建议 | 水平定位 中级以下，或多项关键题答不出/答错；或简历与回答明显不符（注水严重） | 中级以下 | 不通过 |

## 等级与评级对应标准（建议等级 ↔ 面试评级，口径必须一致）

建议等级与面试评级必须按同一套逻辑给出，**二者在报告中同时输出且互相对应**：

| 建议等级（水平定位 + 回答质量） | 面试评级 | 说明 |
|---|---|---|
| 专家 / 资深 | **A** | 原理与实践俱佳、匹配度高，无硬伤 |
| 高级（表现优秀） | **A** | 无明显短板 |
| 高级（有 1-2 个短板） | **B** | 基本胜任 |
| 中级偏上 ~ 高级边缘 | **B 或 C** | 视短板数量与 JD 匹配度 |
| 中级 ~ 中级偏上 | **C** | 未达高级岗位要求 |
| 中级以下 | **D** | 明显不匹配 |

评级规则：
- **先定建议等级，再按上表映射出面试评级**，保证两者一致；评定基线 = 第 1 题水平定位（如有）+ 整体回答质量 + 五个维度 + JD 匹配度；
- **真实性是重要否决项**：简历与回答明显不符、量化指标对不上 → 至少降一级（A→B、B→C、C→D）；
- **未提问的题目不参与评估，不因未提问而降级**；水平定位未勾选时按已答题目回答质量推断，并注明「按回答质量推断」；
- 评级与录用建议映射：A→推荐；B→推荐二面；C→待定（谨慎）；D→不通过。

## 评估报告结构（参考 [assets/评估报告模板.md](assets/评估报告模板.md)）

1. **头部信息**：候选人、应聘岗位、面试日期、评估日期、评估说明（是否打过分、哪些题未问）
2. **一、面试基本情况与核验补充**：已问/未问题目清单、现场确认的核验信息（所在地、青岛接受度、期望薪资、外包、学历验证码等）
3. **二、等级评定**：建议等级 + **面试评级（A/B/C/D）** + 等级与评级对应说明 + 判定依据
4. **三、分题评估（可选）**：每题回答质量摘要（答得好/一般/答不出 + 一句评价）
5. **四、维度评估**：Java 基础扎实度、技术广度、深度、实战经验、系统设计与架构能力、固定 JD 匹配度、外包/青岛岗位适配度
6. **五、强项 / 短板 / 综合评语**
7. **六、录用建议**：通过 / 待定 / 不通过 + 理由（与面试评级对应：A→推荐、B→推荐二面、C→待定、D→不通过）
8. **七、二面重点关注清单（可选）**：回答薄弱的关键技术项与需现场核验项（薪资、学历、量化指标等），供项目经理二面验证
