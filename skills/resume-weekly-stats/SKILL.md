# 简历库周报统计（JAVA + 前端 · 面试官×岗位维度 · 保存本地Markdown）

## 数据源（固定，勿改）

- 多维表格：岗位招聘管理文档
- base_token：`ILuybtceKau2X2sbLx0c4SRpnOg`
- 数据表：简历库，table_id：`tblLcOSapd0nUuhl`
- 涉及字段：候选人姓名 `fld7t1q8QJ`、岗位 `fldPVWgXor`、简历添加日期 `fldbxJYEP6`（created_at）、简历添加时间 `fldCHAJY90`（created_at）、面试时间 `fldzXgAnId`（datetime）、面试官 `fldv2ruekN`（user）、面试状态 `fldjcGWkH9`（select）、面试评级 `fldZLXjLTc`（select）、二次沟通情况 `fldhlaGmat`（text）、期望薪资 `fld0kx4vuF`（formula）、最快到岗时间 `fldusj92Ak`（formula）

## 时间窗口（每次执行实时计算，勿用固定日期）

- **起点**：当前系统时间之前最近的一个周六 00:00:00；**终点**：当前系统时间。
- 计算规则（Python 实现）：`days_since_sat = (now.weekday() - 5) % 7`，若为 0 则取 7；`start = now - timedelta(days=days_since_sat)` 后归零到当天 00:00:00。
  - 今天是周六 → 起点为 7 天前的周六
  - 今天是周日 → 起点为昨天（周六）
  - 其他日子 → 本周最近的一个周六（周一=2天前、周二=3天前、周三=4天前、周四=5天前、周五=6天前）

## 统计范围与维度

- **只统计岗位含 `JAVA`（大小写不敏感）或 `前端` 的记录**，其他岗位一律不统计。
- 岗位类别：优先判断 JAVA，再判断 前端（`JAVA-开发工程师` 等 → JAVA；含“前端”的岗位 → 前端）。
- 统计维度：**面试官 × 岗位**——每位面试官下分别统计 JAVA、前端 两组数字与小计。
- 展示顺序：**先汇总（各岗位汇总数字表 + 全部已面试候选人明细，明细含岗位、面试官列），后各面试官数据**（每位面试官一份岗位数字表）。

## 统计口径（4 个数字，互不排斥）

1. **需要面试的简历数**：简历添加日期 ∈ [起点, 现在]
2. **已完成面试简历数**：面试时间 ∈ [起点, 现在]
3. **简历不合适数量**：面试状态 ∈ {简历不合适, 联系不上} 且 面试时间 ∈ [起点, 现在]
4. **优秀简历数量**：面试评级 ∈ {A（极好）, B（不错）} 且 面试时间 ∈ [起点, 现在]

（用户口径：第 1 项按“简历添加日期”，第 2/3/4 项均按“面试时间”判断是否在时间范围内；第 3 项同时包含“简历不合适”和“联系不上”两种面试状态；简历不合适/联系不上的人仅合并进明细表展示，不计入“已完成面试简历数”。）

## 已面试候选人明细

- **收录**：面试时间 ∈ [起点, 现在] 的记录，以及 面试状态 ∈ {简历不合适, 联系不上} 且 简历添加日期 ∈ [起点, 现在] 的记录（保证简历不合适/联系不上的人一定出现）。
- **列**：序号、姓名、**岗位**、**面试官**、简历添加时间、面试时间、面试评级、期望薪资、最快到岗、原因。
- **面试评级列**：简历不合适/联系不上 → 显示面试状态（优先于评级）；否则有评级显示评级（如“A（极好）”“B（不错）”）；其余“空”。
- **原因列**：仅简历不合适/联系不上展示“二次沟通情况”（多行合并为单行，缺失留空）；其余留空，不写“空”字。
- **排序**：A（极好）→ B（不错）→ C（一般）→ D（未通过）→ 简历不合适/联系不上 → 空白；组内按面试时间从早到晚（有面试时间的排前面）。

## 执行步骤

1. 运行脚本：`python scripts/query_resume_weekly_stats.py`（自动计算时间窗口 → 服务端按“面试官非空”筛选并分页拉取 → 本地过滤 JAVA/前端 岗位 → 按 面试官×岗位 分组统计 → 先输出汇总（岗位数字表 + 全部明细），后输出各面试官数据 → 完整报告打印到控制台并**保存为本地 Markdown 文件** `G:\Documents\岗位\简历库周报_{起点日期}_{今天日期}.md`，末尾打印 `[已保存] {路径}`）。
2. 若脚本不可用（如 lark-cli 未配置），手工执行：
   - `lark-cli base +record-list --base-token ILuybtceKau2X2sbLx0c4SRpnOg --table-id tblLcOSapd0nUuhl`，带上 `--field-id 候选人姓名 --field-id 岗位 --field-id 简历添加日期 --field-id 简历添加时间 --field-id 面试时间 --field-id 面试官 --field-id 面试状态 --field-id 面试评级 --field-id 二次沟通情况 --field-id 期望薪资 --field-id 最快到岗时间`，并传筛选 `--filter-json '{"logic":"and","conditions":[["面试官","non_empty"]]}'`，分页参数 `--limit 200 --offset <n>`（下一页 offset += 本页行数，直到 `has_more=false`）。
   - 拉全后：本地过滤岗位含 JAVA / 前端的记录，按面试官×岗位分组计算，按“输出格式”输出。
3. 输出报告。

- 汇总明细一张表列全部候选人（含岗位、面试官列）；各面试官小节只列岗位数字表 + 小计，不再重复明细。
- 各面试官按“已完成面试数（合计）”从多到少排列（相同按姓名）；只列出窗口内有数据（4 个数字任一 > 0）的面试官；本周无 JAVA/前端记录时输出“（本周无 JAVA / 前端岗位记录）”。

- 明细表行数可能大于“已完成面试简历数”：后者仍按面试时间统计，明细表额外包含简历不合适/联系不上（按简历添加日期）的记录。

## 保存为本地 Markdown 文件

- 运行脚本后，除控制台输出外，完整报告保存为 `G:\Documents\岗位\简历库周报_{起点日期}_{今天日期}.md`（如 `简历库周报_2026-10-24_2026-10-30.md`），UTF-8 编码。
- 文件内容与控制台输出一致（标题、汇总、各面试官数据）；脚本末尾打印 `[已保存] {路径}` 表示落盘成功。

## 注意事项

- 数据全部来自真实表；面试官字段为人员字段，以 user id 分组（展示姓名），不按姓名文本筛选；同一姓名可能是不同 user id，以 id 分组为准。
- JAVA/前端 岗位判定：岗位字段文本含 `JAVA`（大小写不敏感）或 `前端`；其他岗位不统计。
- 时间窗口每次执行时按当前系统时间实时计算，不得套用历史固定日期。
- 4 个数字互不排斥，各自独立计数（同一记录可能同时计入多个数字）；合计 = 各组数字直接相加。
