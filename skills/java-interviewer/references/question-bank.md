# 企业级 Java 面试题库参考

用途：作为出题覆盖面清单与示例参考。按候选人简历/JD 选择相关模块；8-12 道题内尽量覆盖多模块，不要求每题都从本库选取。

## 模块与考察点

### 1. Java 核心

- 面向对象：封装/继承/多态、接口与抽象类的选择
- 集合：ArrayList/LinkedList、HashMap 原理（扩容、红黑树、线程不安全）、ConcurrentHashMap
- 泛型、异常体系、equals/hashCode 契约
- Stream/函数式：常用操作、与 for 循环的取舍
- 字符串：String/StringBuilder/StringBuffer

### 2. 并发编程

- 线程池：核心参数、拒绝策略、任务队列选择、大小如何设置
- synchronized / ReentrantLock 区别、volatile 语义
- JUC 容器：ConcurrentHashMap、CopyOnWriteArrayList
- CompletableFuture 异步编排
- 实际场景：多线程数据不一致、线程池耗尽、死锁排查

### 3. Spring / Spring Boot

- IoC/AOP 的理解、Bean 生命周期
- Spring Boot 自动配置原理
- 事务：@Transactional 失效场景、传播行为、隔离级别
- 循环依赖（了解程度）、常用注解

### 4. 数据访问层

- MyBatis：#{} vs ${}、一级/二级缓存、批量插入优化
- JPA/Hibernate：懒加载、N+1 问题
- 框架事务与数据库事务的关系

### 5. MySQL

- 索引：B+ 树、最左前缀、索引失效场景、覆盖索引
- SQL 优化：慢查询定位（explain）、分页优化
- 锁与事务：隔离级别、MVCC、死锁
- 分库分表：场景、方案、分布式 ID

### 6. Redis

- 数据结构与使用场景
- 缓存穿透/击穿/雪崩及解决方案
- 缓存与数据库一致性（先删缓存、延迟双删等权衡）
- 分布式锁（Redisson 实现、注意事项）

### 7. 消息队列

- 选型：Kafka/RabbitMQ/RocketMQ 的场景差异
- 可靠消息：生产端确认、消费幂等、消息堆积
- 顺序消息、事务消息

### 8. 微服务与分布式

- 服务拆分原则、注册中心/配置中心选型
- 分布式事务：2PC/TCC/本地消息表/Saga 权衡
- 接口幂等、限流（令牌桶/滑动窗口）、熔断降级
- 链路追踪、服务网格（视水平而定）

### 9. 工程实践

- 代码规范、Code Review、单元测试/集成测试
- 日志规范、监控告警
- CI/CD、Docker/K8s 基本使用
- 线上故障排查流程（CPU 高、内存高、接口慢、Full GC）

### 10. 系统设计场景题（视职级）

- 短链接系统、秒杀系统、IM、订单系统等
- 高并发下一致性/可用性权衡（CAP）

## 水平分层示例

同一主题按水平出不同深度题：

- 初级：ArrayList 和 LinkedList 的区别？
- 中级：HashMap 为什么线程不安全？ConcurrentHashMap 怎么保证线程安全？
- 高级：线上 HashMap 死循环/CPU 飙升如何定位与修复？为什么 1.8 引入红黑树？
- 资深：设计一个线程安全的 LRU 缓存，说明并发与性能权衡。

## 常用追问（用于区分水平）

- 「你实际遇到过吗？当时怎么排查的？」— 验证实战
- 「为什么这样做？有其他方案吗？」— 验证深度
- 「如果数据量/并发翻 10 倍，你的方案还成立吗？」— 验证设计
- 「这个方案有什么缺点？如何权衡？」— 验证工程判断

（以上追问用于**融入问题正文**，不单独列「追问」小节）

> 场景化提醒：本库条目的直问式写法（如「HashMap 原理」「事务隔离级别」）是「考察点清单」，**正式出题时必须按 SKILL.md「问题场景化改写规范」转成场景问**（如「线上 HashMap 死循环导致 CPU 飙升，你怎么定位」而非「HashMap 为什么线程不安全」）；禁止把清单条目原样当作问题正文。
> 结构提醒：正式出题**不输出「考察方向」与「得分点」**，每题标题下方标注「题目来源：岗位 JD / 简历 / 岗位 JD + 简历」（考点来自固定 JD → 岗位 JD；来自简历亮点技术深挖 → 简历；第 1 题技术概览 → 岗位 JD + 简历；**不设单独的真实性核验题**）；标准参考答案按「方案要点 → 为什么/权衡 → 常见坑 → 落地细节」四层写足 4-6 个要点并保证技术正确，**每个追问（含第 1 题按 JD 的追问）都必须有明确答案，禁止模糊话术**。

## 11. 第 1 题（最近项目技术概览题）设计

**默认第 1 题固定请候选人讲述最近一个项目的业务链路、负责的技术模块与技术栈**，再由面试官**根据岗位 JD 明确追问 1-2 个具体技术问题**（追问须对应 JD 核心能力、问题具体可答），**不以「简历写了什么技术点」直接开场**。它承担项目真实性核验与技术水平初判（真实做过才能答出细节），但**不设水平定位题、不设水平定位勾选**，也不设单独的真实性核验题。第 1 题追问的技术点与后续专题题**主题两两不重复**；第 1 题第 3 问预告的技术点**只点名、不展开**，由后续对应专题题展开（「点名 vs 展开」一一对应，见 SKILL.md「题目主题规划」）。以下为设计示例，使用时按候选人简历替换项目与追问点，禁止原样套用。

### 示例 A：有电商/交易类项目的候选人

- 第 1 题（技术概览 + JD 追问）：
  - 问题 1：先讲一下你最近这个项目（全域电商营销系统）的业务链路、你负责的技术模块，以及用到的技术栈？
  - 问题 2（JD 追问·MySQL 调优）：你们项目里数据库用在哪？有没有遇到过慢 SQL 或数据量大的查询，当时怎么定位、怎么优化的？
  - 问题 3（JD 追问·高并发）：你们优惠券秒杀场景的并发量大概多少？如果并发翻 10 倍，你判断哪里会先撑不住？
  - 追问口径：答案要具体——讲出表结构、索引、SQL 优化手段、压测/线上指标（预期：能讲 Redis 预扣减、Lua、限流阈值等细节）。
  - 预告点名：讲完我会就其中 1-2 个技术点深入追问（如订单支付一致性、缓存一致性，具体实现由专题题展开）。
- 第 2 题（专题展开·并发/一致性）：库存扣减怎么做不超卖？（预期：条件更新 UPDATE ... WHERE stock>=?、事务、Redis 预扣减与回滚、对账补偿）；并发压测过吗？为什么这么选？
- 第 3 题（专题展开·架构权衡）：如果流量翻 10 倍，方案哪里先撑不住？（预期：容量评估、分库分表、最终一致 vs 强一致权衡）

### 示例 B：有 Redis 缓存项目的候选人

- 第 1 题（技术概览 + JD 追问）：
  - 问题 1：先讲一下你最近这个项目（如本地生活服务平台）的业务链路、你负责的技术模块，以及用到的技术栈？
  - 问题 2（JD 追问·Redis）：你们项目里 Redis 用在哪几个场景？线上有没有遇到过缓存和数据库数据对不上的情况？当时怎么发现、怎么处理的？
  - 问题 3（JD 追问·消息队列）：你们项目里消息队列（RabbitMQ/Kafka）承担了什么？有没有遇到过消息积压或重复消费？
  - 追问口径：答案要具体——讲出缓存读写策略、MQ 消费幂等方案、实际故障排查过程（预期：能讲先更新库再删缓存、手动 ACK、唯一键去重等细节）。
  - 预告点名：讲完我会就其中 1-2 个技术点深入追问（如缓存穿透/击穿/雪崩、热点 key 治理，具体实现由专题题展开）。
- 第 2 题（专题展开·缓存三兄弟）：缓存穿透、击穿、雪崩分别是什么？分别怎么防？（预期：布隆过滤器/空值缓存、互斥锁/逻辑过期、随机过期/多级缓存）
- 第 3 题（专题展开·架构权衡）：多级缓存/热点 key/流量翻倍怎么设计？（预期：逻辑过期、失效策略、容量与成本权衡）

出题注意：第 1 题**固定先讲业务链路/负责模块/技术栈（概览），再按岗位 JD 追问具体技术点**；第 1 题追问的技术点与后续专题题主题不重叠；第 1 题预告的技术点由第 2 题起的专题题逐一展开（并发、事务、缓存、MQ、数据库、三方对接等），每题一个明确技术主题，各题主题与问题正文核心考察关键词跨题两两不重复。真实性核验不单独成题，通过每题场景追问逼出真实经历细节（具体表/参数/命令/踩坑）。水平判断以真实经历信号优先：能讲具体实现=中级；能讲权衡踩坑=高级；能讲量化演进=资深/专家；背题举不出真实案例的不评为高级以上。**参考答案必须包含第 1 题每个追问的明确答案，禁止模糊话术。**
