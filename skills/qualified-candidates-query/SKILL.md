# 合格候选人查询

按岗位名称一次性给出“岗位需求 + 合格候选人名单”。每次执行都实时查询表格最新数据，不使用缓存、不沿用历史结果。

## 数据源（固定，勿改）

- 多维表格：岗位招聘管理文档，base_token：`ILuybtceKau2X2sbLx0c4SRpnOg`
- “海尔岗位需求”表，table_id：`tblwoDmrLwp5SCut`
  - 第一列为 `文本`（整条记录的原始 JSON 字符串），**按要求不展示**；其余列全部列出：
    岗位、级别、需求团队、需求人数、人天单价、岗位状态、用人开始时间、用人结束时间、发布人、发布时间、已投递人数、发布周度、岗位要求
- “简历库”表，table_id：`tblLcOSapd0nUuhl`（约 7000+ 条，必须分页）
  - 用到字段：候选人姓名 `fld7t1q8QJ`、面试官 `fldv2ruekN`、面试时间 `fldzXgAnId`、面试评级 `fldZLXjLTc`、
    期望薪资 `fld0kx4vuF`、毕业时间 `fld6qhdVMg`、电话 `fldl4IBTnl`、备注 `fld2cR4MYJ`、
    目前所在地 `fld3d5TkoG`、籍贯 `fldVL6r7ce`、最快到岗时间 `fldusj92Ak`、技术评价 `fld0s40dEI`、
    岗位 `fldPVWgXor`、面试状态 `fldjcGWkH9`、简历状态-海尔 `fldqBeyNxD`

## 入参

- **岗位名称**：技能调用时传入；**未传则默认 `JAVA-开发工程师`**。
- 岗位名称直接用于“简历库”的 `岗位 == 岗位名称` 精确筛选（表中选项值：`JAVA-开发工程师`、`前端-开发工程师`、`测试-测试工程师`、`大数据-ETL/EDW-开发工程师`、`python开发` 等）。
- 用户只给简写时先归一化成表中的选项值再查询，如 `java`→`JAVA-开发工程师`、`前端`→`前端-开发工程师`、`测试`→`测试-测试工程师`；归一化不了就按用户原词精确匹配，结果为空则提示可选岗位有哪些。
- “海尔岗位需求”的匹配关键词：取岗位名称破折号（-）前的部分，如 `JAVA-开发工程师`→`JAVA`、`前端-开发工程师`→`前端`；无破折号时用全名。用关键词做岗位名包含匹配（不区分大小写），因此 `JAVA` 会同时命中 `JAVA-开发工程师` 与 `JAVA应用实施-开发工程师`。

## 步骤1：岗位需求列表

1. 分页拉取“海尔岗位需求”全表（约 86 条，`--limit 200` 一页足够，仍按 `has_more` 判断）。
2. 按关键词过滤出该岗位的全部记录；**不按岗位状态过滤**（招聘中、已关闭都要列，状态本身是列内容）。
3. 表格输出，列 = 序号 + 除第一列 `文本` 外的所有列；排序：`招聘中` 排在前，其余按发布时间倒序。
4. `岗位要求` 单元格内的换行压成空格，保持全文，不截断。

## 步骤2：候选人筛选

1. 服务端筛选：`岗位 == 岗位名称` 且 `面试状态 == 已初试`；分页拉全量（offset 递增直到 `has_more=false`）。
2. 本地过滤（Python 侧，避免服务端过滤不支持“不等于某选项”）：
   - `面试评级 == D（未通过）` → 排除；评级为空 → **保留**。
   - `简历状态-海尔 ∈ {被占用, 已下架, 已入职, 找到工作}` → 排除；为空 → **保留**。
3. 排序：`面试评级` A（极好）→ B（不错）→ C（一般）→ 空；同评级内 `面试时间` 倒序；无面试时间排在同评级最后。

## 步骤3：表格输出（12 列）

`候选人姓名 | 面试官 | 面试时间 | 面试评级 | 期望薪资 | 毕业时间 | 电话 | 备注 | 目前所在地 | 籍贯 | 最快到岗时间 | 技术评价-面试问题`

字段规则：

- **面试官**：user 字段取姓名（多人用“、”连接）。
- **面试时间**：统一输出 `YYYY-MM-DD`，兼容表里带时分秒的 ISO 写法（`2026-04-25T10:35:00.000+08:00` → `2026-04-25`）。
- **面试评级**：原样输出（`A（极好）`/`B（不错）`/`C（一般）`），空值写“未评级”。
- **技术评价-面试问题**：从 `技术评价` 自由文本中抽取 `面试问题：` 段的内容（该列是面试官手写的多段文本，常见格式为 `1.沟通情况 / 2.擅长哪些技术栈 / 3.技术水平评价 / 7.面试问题`，数字序号不固定）。
  - 抽取范围到下一个分段标题为止；分段标题包括“带冒号的标签行”和“不带冒号的编号小标题”（如 `8.最近是否面试海尔海信`），避免把后续段落粘进来。
  - 文本里没有 `面试问题` 段时，退回 `技术水平评价`/`技术评价`/`个人意见` 段，并在前面标注来源，如 `（技术水平评价）高级`。
  - 两段都没有时写“无面试问题记录”。
- 单元格内的换行替换为“；”，竖线 `|` 替换为全角 `｜`，保证 Markdown 表格不错列。

## 执行

在技能根目录下运行（lark-cli 需已登录，可用 `--as user` 身份读取表格）：

```bash
# 默认查 JAVA-开发工程师
python scripts/query_qualified_candidates.py

# 指定岗位名称
python scripts/query_qualified_candidates.py "前端-开发工程师"
```

脚本一次输出：岗位需求表（含条数与“招聘中/其他状态”统计）+ 合格候选人表（含总数与 A/B/C/未评级 分布）。

## 输出纪律

- 所有数据必须来自实时查询结果，**不得编造候选人、薪资、电话或岗位要求**；查不到就如实说明“未查询到满足条件的候选人”。
- 岗位需求表中找不到含关键词的岗位时，先照实提示，再继续输出候选人部分（候选人只依赖岗位名称，不依赖岗位需求表）。
- 若用户改了口径（如更换岗位、放宽评级、要求显示已下架人员、要求含 `文本` 首列），按用户最新要求执行，并同步更新本文件与脚本。
- lark-cli 单页上限 200 条，必须按 `has_more` 翻页，否则会漏人。
- 候选人结果较多时（百人级）直接给完整表格；只有在用户明确要求“只看 A 级/B 级以上”时才按评级裁剪，并说明已裁剪。
