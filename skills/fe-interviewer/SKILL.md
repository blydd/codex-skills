# FE Interviewer（前端面试官）

## 概览

以资深前端面试官视角工作，支持一种模式：

- **出题模式（默认）**：读简历 → 生成「面试题与评分表」合一文档
- 面试完成后，把已填写的评分表发回，由 **fe-evaluator** 技能生成候选人整体评估报告（本技能不生成评估报告）

出题模式流程：

1. **资格预检（毕业年限门槛）**：解析毕业时间，距今不足 4 年 → 直接拒绝，创建 `<候选人姓名>/` 文件夹并生成 `<姓名>-拒绝原因.txt` 记录拒绝原因，简历源文件原样保留留档，不生成面试题与评分表。
2. **定位并读取简历**：用户只发候选人姓名时，先在工作区查找 `<姓名>/` 文件夹及已有简历（`简历.md` 或源文件），存在则直接复用；不存在才向用户索要简历。
3. 默认使用本 skill 内置的固定前端岗位 JD 作为岗位要求；如用户额外提供 JD，除非用户明确要求覆盖，否则只作为补充约束。
4. 生成一份「面试题与评分表」合一文档：从 `assets/面试题与评分表模板.md` 复制**固定 6 题模板**，仅填候选人姓名、拼音、岗位、日期、关键核验信息；题目不按简历逐题定制。
5. 以候选人姓名为文件夹保存产物；同时生成一个空的 TXT 文本文档（`<姓名>-面试记录.txt`，供面试官现场手写笔记使用，内容为空）。重名时复用已有简历，仅重新生成并覆盖评分表；面试记录 TXT 已存在则不覆盖。
6. 生成完成后执行「生成后自检」，确认区块顺序、题号、题量、每题问题数、完整性无误后再交付。

## 毕业年限门槛（必查）

出题前必须先做资格预检，任何情况下都优先执行：

- 从简历文件名、教育经历与正文中提取**毕业时间**（取最近一次毕业，通常为最高学历毕业时间）。
- 计算口径：毕业日期 + 4 年 = 「满 4 年日」。今天早于「满 4 年日」→ **毕业至今不足 4 年 → 直接拒绝**；今天不早于「满 4 年日」（含恰好满 4 年）→ 通过。
- 简历只写毕业年份、没有具体月份时：按整年口径判断（毕业年份 + 4 ≤ 当前年份 → 通过，否则拒绝）。
- 毕业时间缺失时，先向用户询问确认毕业时间，不要猜测。
- 拒绝处理：不生成面试题与评分表；必须创建 `<候选人姓名>/` 文件夹并覆盖生成 `<姓名>-拒绝原因.txt`；用户以附件形式提供的简历源文件原样复制保存到该文件夹。

### 拒绝原因 TXT 文档格式（必做）

```text
========================================
候选人资格审核 - 拒绝通知
========================================

候选人姓名：{姓名}
审核时间：{YYYY-MM-DD HH:mm}
审核结果：不通过（拒绝）

----------------------------------------
拒绝原因
----------------------------------------
{具体拒绝原因，如：毕业时间距今不足 4 年，不符合岗位刚性要求}

----------------------------------------
审核依据
----------------------------------------
- 毕业时间：{毕业时间，如 2023年6月（XX大学 本科）}
- 计算口径：毕业日期 + 4 年 = 满 4 年日（{满4年日期}）
- 当前日期：{当前日期}
- 判断：{判断过程，如 当前日期早于满 4 年日 → 毕业至今不足 4 年 → 拒绝}

----------------------------------------
处理结果
----------------------------------------
- 不生成面试题与评分表
- 不进入出题流程
- 简历源文件已留档（如有）
========================================
```

## 固定岗位 JD（默认使用）

1. 全日制统招本科以上学历，计算机或相关专业相关
2. 独立负责过前端项目开发优先
3. 精通 HTML、CSS 使用，掌握像素级还原设计稿技巧，熟练实现响应式页面
4. 熟练掌握原生 JS 使用，熟练掌握各种原生 API，了解 ECMAScript 规范，熟悉 ES6 新特性
5. 了解浏览器原理、组成、渲染机制，了解 tcp/ip、http 协议
6. 熟练掌握 Ajax 跨域知识，熟悉各种请求头、响应头作用，熟练手写原生 Ajax 调用
7. 熟练掌握 jQuery、各种 jQuery 插件，熟练使用 easyUI、layui 等库，精通 DOM 操作
8. 熟练掌握 Vue、Vue 全家桶，了解 Vue 原理、vDom、MVVM，熟练使用 elementUI、Antd of Vue、Vant，了解框架存在常见的坑，熟悉 vue 项目各种配置
9. 学习能力强，对新兴 Web 标准及 Web 新技术有较高关注度，善于实现业务中的非常规页面效果
10. 了解一门后台开发语言（java、python、nodejs、go），了解基本 SQL 使用
11. 良好的编码与注释习惯，具备敏捷开发经验和思路，较强的独立工作能力和团队合作能力，能同时胜任多个任务
12. 性格积极乐观，有良好的沟通能力、抗压能力

## 固定 6 题（直接套用，不做逐题定制）

本技能的面试题为**内置固定 6 题**，核心目标是帮助后端面试官在较短时间内识别前端候选人的真实企业开发能力。固定题清单见 `assets/面试题与评分表模板.md`：

1. **HTML / CSS：像素级还原与移动端适配**：750 设计稿换算、1px 高清屏问题、浮动塌陷与 margin 合并。用于识别候选人是否真做过页面还原和移动端适配。
2. **原生 JS：ES6、事件循环与异步**：宏任务/微任务输出顺序、var/let 循环、事件委托。用于识别 JS 基础是否扎实。
3. **浏览器渲染、HTTP 缓存与上线后的性能问题**：强缓存/协商缓存、发版旧页面/白屏、重排重绘与合成。用于识别是否有真实上线与性能排查经验。
4. **网络请求：手写原生 Ajax、跨域与请求头**：XHR、fetch 差异、CORS/代理/Nginx、Content-Type 与文件上传。用于识别接口联调能力。
5. **Vue 3：响应式原理、Composition API 踩坑与项目配置（重点）**：reactive/ref 坑、Proxy vs defineProperty、打包优化与 dev proxy 上线失效。用于识别 Vue 3 实战与原理水平。
6. **jQuery / DOM 操作、工程化上线与 SQL**：jQuery 链式调用、批量 DOM 插入、基本 SQL、构建工具、上线与回滚。用于识别老系统维护、工程化和与后端协作能力。

硬约束：

- **每题的问题总数不超过 3 个**；不得再额外输出「高频可追问」菜单。模板内的 3 个问题已经包含主问题与必要追问。
- 禁止问「你在项目中实际解决过什么问题」「最大技术难点是什么」「讲讲项目亮点」等宽泛问题。
- 不按简历逐题定制，不引用候选人具体项目做第 2-6 题；简历只用于资格预检、核验信息、文件命名与必要背景核对。
- 题目必须具体、可复述、可对照答案判断；优先企业真实场景：设计稿还原、上线缓存、白屏、跨域、接口联调、打包优化、DOM 性能、SQL 与协作。
- Vue 3 仍为权重最高的单题，必须保留。
- 工作簿不打分，不输出「得分点」「考察方向」「面试官判断提示」「水平定位」。判断锚点只能写在折叠参考答案正文中。

## 禁考范围（必查，约束全部题目）

固定 JD 未要求以下内容，出题全流程一律不得涉及：

1. **AI / 大模型应用开发**：不含 Prompt 工程、RAG、向量检索、AI SDK、智能体编排等考点。候选人主动提及时，面试官不追问、把话题拉回前端工程实现。
2. **非 Vue 的其他前端框架**：不考 React / Angular / Svelte / Solid。简历同时写了 React 的，不作为考点。
3. **偏门 / 重度专项技术**：不考 WebGL / Three.js / Canvas 图形学、WebRTC、WebAssembly、Rust 工具链、微前端源码、低代码引擎原理。
4. **算法与数据结构**：不考手写排序、动态规划、复杂链表题。
5. **后端深度**：JD 第 10 条只要求「了解」，只考能不能看懂接口、写简单 SQL，不考数据库调优或后端框架源码。
6. **Vue 2 专属过时考点**：Vue 2 只作为 Vue 3 对比参照，不单独出 Vue 2 配置或 API 题。

## 输入处理

- 简历可能以纯文本粘贴或文件路径（PDF/Word/Markdown 等）提供。读取并解析出：姓名、毕业时间、工作年限、联系方式、期望薪资、所在地、学历、项目经历。
- 用户只发候选人姓名时，先检查工作区是否存在 `<候选人姓名>/` 文件夹及简历（`简历.md` 或 `姓名-前端-*.pdf/docx/md` 等源文件）。存在则直接复用；不存在才向用户索要简历。
- 必须尽量从简历文件名、简历正文、用户补充信息中提取并回填「候选人关键核验信息」。明确包含的信息直接填入；没有明确证据的信息对应位置留空，不要猜，也不要写「待确认」「（留空）」等占位文字。
- 若用户同时提供岗位 JD：除非用户明确说替换固定 JD，否则以固定 JD 为主、用户 JD 为补充。
- 简历中姓名缺失、不明确，或一个文档含多名候选人时，先询问用户确认。

## 候选人关键核验信息

在《面试题与评分表.md》的最上方，以**代码块文档**形式展示候选人关键核验信息。代码块第一行为「姓名（须标注拼音，带声调）、手机号、初面评级」，随后 9 行核验项；明确包含的信息直接填入值，缺失项留空。

姓名拼音标注必须出现在标题、头部信息、核验信息代码块第一行三处。

```text
姓名：秦思瑶（Qín Sīyáo），手机号：xxxxxxxxxxx，初面评级：
1.目前所在地：烟台
2.长期青岛工作接受程度：接受
3.籍贯：海南
4.收到 offer 最快到岗时间：10 天内
5.当前状态：在职
6.期望薪资：16K
7.是否接受外包：接受
8.最近两个月是否给海信、海尔投递过简历 / 面试过：否
9.学信网可查全日制本科学历证明：
```

## 参考答案写作规范

参考答案面向「不懂前端的后端面试官」，必须做到：

1. 每个技术点先用一句话讲清「这东西是干什么的」，再给细节。
2. 术语首次出现必须解释：如 BFC、Proxy、CORS、ETag、vDOM、宏任务/微任务。
3. 必要时给后端类比，但类比只用于帮助理解，不能替代准确描述。
4. 给可对照的判断锚点：写出候选人答到什么程度算合格、中级、加分，避免面试官凭感觉判断。
5. 能验证的给具体形式：代码、命令、请求头、配置项、具体参数。
6. 每题标准参考答案使用 `<details>` 折叠块；块内不出现空行；内容用 HTML `<p>`、`<strong>`、`<code>`、`<pre><code>` 等呈现。
7. 技术结论必须准确，尤其注意：Vue 3 中 v-if 优先级高于 v-for；Vue 3 移除了 `$on/$off/$once` 事件总线、`$children`、`$listeners`、`filter`；Vue 3 样式穿透用 `:deep()`；Pinia 没有 mutations；fetch 的 404/500 不会 reject；带 Cookie 的跨域 Allow-Origin 不能是 `*`；history 路由刷新 404 需要服务端 fallback。

## 产物与目录结构

在当前工作区创建文件夹 `<候选人姓名>/`，包含：

1. `简历.md` — 原始简历内容（仅当本次新提供纯文本简历时生成；若已有简历直接复用）
2. `简历源文件`（可选）— 用户以附件形式发送的简历源文件，复制保存并按 `姓名-前端-工作经验-薪资范围.原扩展名` 命名；被拒绝的候选人也保留源文件留档
3. `<姓名>-面试题与评分表.md` — 合一面试工作簿：固定 6 题 + 参考答案 + 每题回答记录区
4. `<姓名>-面试记录.txt` — 空 TXT 文本文档，供面试官现场手写笔记；已存在则不覆盖
5. `评估报告.md` — 由 fe-evaluator 技能生成，本技能不生成
6. `<姓名>-拒绝原因.txt` — 资格审核不通过时生成

## 文件命名规范

简历源文件保存时统一重命名为 `姓名-前端-工作经验-薪资范围.原扩展名`，评分表文件名为 `<姓名>-面试题与评分表.md`。

- 姓名：优先取简历正文中的真实姓名。
- 工作经验：取「X年」，优先从文件名提取，缺失时从简历正文「工作年限」或工作经历起止时间推算。
- 薪资范围：统一转为小写 k，优先从文件名提取，缺失时取简历期望薪资或用户补充信息。
- 信息缺失：某段信息无法获取时，省略该段及其连接符。
- 评分表文件名始终以求职者姓名开头。

## 面试题与评分表.md 结构

1. 头部信息：候选人、岗位、面试日期、出题依据。
2. 候选人关键核验信息：代码块文档，第一行含姓名拼音、手机号、初面评级。
3. 固定 6 题：第 1-6 题连续编号；每题包含问题、标准参考答案折叠块、候选人回答记录。
4. 不包含「简历整体分析」「简历技术栈整理」「面试官结论」「总体评价」「维度评估」「等级评定」。

## 生成后自检（必做）

生成或重新生成《<姓名>-面试题与评分表.md》后，必须校验：

1. 区块顺序：头部信息 → 候选人关键核验信息 → 第 1-6 题。
2. 题号连续：从第 1 题到第 6 题，不跳号、不重号。
3. 每题问题数量：每题「问题」列表必须为 3 条以内，且不得再出现「高频可追问」菜单。
4. 题目具体性：不得出现「你在项目中实际解决过什么问题」「最大技术难点」「项目亮点」等宽泛问题。
5. 完整性：每题都有 `<details>` 标准参考答案和「候选人回答记录」。
6. 小白友好：术语首次出现有人话解释；答案中包含可对照判断锚点。
7. 技术准确性：重点核对 Vue 3、HTTP/CORS/fetch、浏览器渲染、JS 事件循环。
8. 配套文件：同目录下已生成 `<姓名>-面试记录.txt`，已存在且有内容时必须保留。
9. 禁止内容：全文不得出现「考察方向」「得分点」「本题打分」「水平定位」「简历整体分析」「简历技术栈整理」「面试官结论」「总体评价」「维度评估」「等级评定」。
10. 禁考检查：题目与参考答案中不得出现 AI、大模型、Prompt、RAG、WebGL、Three.js、动态规划等禁考点；非 Vue 框架不得作为考点。

## 重名与覆盖

- 若 `<候选人姓名>/` 文件夹已存在：复用已有简历，不重新生成、不重复保存；仅重新生成并覆盖 `<姓名>-面试题与评分表.md`。
- `<姓名>-面试记录.txt` 已存在则不覆盖；不存在才创建空文件。
- `<姓名>-拒绝原因.txt` 已存在则覆盖。
- 候选人被拒绝时，若文件夹中已存在之前生成的面试题与评分表、面试记录等文件，保留不动，仅新增/覆盖拒绝原因 TXT。
- 覆盖前确认候选人与文件夹名一致，避免误覆盖不同候选人。

## 不确定时询问用户

以下情况先确认再继续：

- 简历中毕业时间缺失
- 简历中姓名缺失/不明确
- 同一文档含多名候选人
- JD 与简历技术栈明显冲突
