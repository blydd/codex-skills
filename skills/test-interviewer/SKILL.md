# Test Interviewer（测试工程师简历核验建档）

## 概览

以资深测试工程师面试官视角对候选人简历做 JD 符合性判断，并完成核验信息建档（**不生成测试题**）：

- **JD 符合性判断（每次必做的前置步骤）**：读简历 + 固定 JD → 判断候选人是否符合岗位要求；**不符合则直接向用户返回不符合原因（明确哪一条不符合），不创建文件夹、不保存简历**；符合才继续
- **建档模式**：判定符合后 → 创建 `<候选人姓名>/` 文件夹、保存原始简历 → 生成「候选人核验信息表」文档（9 项关键核验信息，缺失项留空并提示用户补充）

建档模式流程：

1. **前置 JD 符合性判断**：按下方「JD 符合性判断」章节逐条核对；**判定不符合 → 直接返回不符合原因并停止，不创建任何文件夹/文件、不保存简历**
2. 读取简历（及可选补充信息）
3. 默认使用本 skill 内置的固定测试工程师岗位 JD 作为岗位要求；如用户额外提供 JD，除非用户明确要求覆盖，否则只作为补充约束
4. 判定符合后：创建 `<候选人姓名>/` 文件夹、保存原始简历源文件
5. 生成「候选人核验信息表.md」：候选人关键核验信息（9 项，代码块文档格式）+ 固定 JD 匹配检查
6. 生成后检查「候选人关键核验信息」：有缺失项时在最终回复中逐项列出，并提示用户补充（面试/沟通前向候选人确认）

## 固定岗位 JD（默认使用）

生成核验信息表时，必须默认使用以下 JD 作为岗位需求基线。即使用户只提供简历，没有单独提供 JD，也必须按本 JD 判断匹配度。

### 岗位职责

1. 依据需求文档及设计文档编写测试用例，保证测试用例正确、全面；
2. 依据测试用例执行手工测试，完成产品集成测试与系统测试；
3. 对应用系统 bug 进行定界、定位与根因分析，对问题进行分类归纳总结；
4. 针对发现的 BUG 及时有效地与相关责任人沟通，督促开发工程师完成修改工作；
5. 日常巡查现有运营产品，保证产品稳定运行；
6. 根据产品设计完成用户手册和其他相关说明文档的编写工作；
7. 具备较强的问题定位和推动能力，协调各个角色高效解决问题。

### 任职要求

1. 第一学历为本科及以上学历；
2. 2 年以上软件测试经验，计算机相关专业；有任意编程语言相关经验者优先；
3. 具有一定的软件测试工作经验，熟悉软件测试流程和规范，对软件测试的难点和解决方案有深入理解；
4. 熟悉软件测试理论和方法，能设计测试框架，包括测试流程、测试用例管理、测试报告等；
5. 具备应用系统 bug 定界、定位、问题根因分析能力，以及问题分类归纳总结能力；
6. 熟悉 Linux 系统常用命令，了解网络基础知识；
7. 熟悉数据库知识，会写 SQL 进行数据查询统计；
8. 具备良好的沟通能力和团队合作精神，能够独立思考并解决问题；
9. 具备强烈的责任心和主动性，态度端正并具备一定的抗压能力。

> **放宽口径**：任职要求第 2 条中的「计算机相关专业」不是绝对门槛——**非计算机相关专业但软件测试经验超过 2 年**者，按放宽口径可判定符合并归档；计算机相关专业仍为优先项。

## JD 符合性判断（前置必做）

每次收到候选人简历（含用户补充信息）后，**先做 JD 符合性判断，再决定是否建档**。判断依据为「固定岗位 JD」的任职要求（若用户明确要求使用其提供的 JD，则以其提供的 JD 为准）。

### 判断方式

- 逐条核对 JD 任职要求与简历证据（工作年限、学历专业、测试经验、技能、项目经历、用户补充信息）；岗位职责不用于硬性判断，作为能力评估参考。
- 只依据简历与用户补充信息中的**明确证据**判断；没有明确证据的条目**不得猜测**，按「证据不足」处理。
- 分两类：
  - **一票否决项（硬性门槛，缺一不可）**：
    1. 第一学历为本科及以上（证据：学历栏；仅大专/学历缺失 → 不符合）
    2. 2 年以上软件测试经验（证据：测试相关工作年限；不足 2 年或无测试经验 → 不符合）
    3. 计算机相关专业（证据：专业名称）：
       - 专业为计算机相关 → 通过；
       - 专业缺失/无法确认 → 证据不足，需用户或候选人补充确认后再判定；无法确认按不符合处理；
       - 明显非计算机相关（如产品设计、市场营销等）→ 不再一票否决：软件测试经验超过 2 年者可放宽通过（归档时在匹配检查与核验备注中标注「专业为放宽项」）；测试经验不足 2 年则不符合
    4. 简历完全未体现软件测试相关工作或技能（无测试岗位经历、无测试技能/项目描述 → 不符合）
  - **能力匹配项（需在简历中体现相关证据；个别缺失不直接淘汰，但要列为「面试现场核验/待补充证据」，缺失过多则整体判定不符合）**：
    - 熟悉软件测试流程和规范、对测试难点与解决方案有理解
    - 能设计测试框架（测试流程、用例管理、测试报告）
    - 能依据需求/设计文档编写全面正确的测试用例，执行手工测试与集成/系统测试
    - bug 定界、定位、根因分析、问题分类归纳能力
    - 缺陷沟通与推动（督促开发修复、协调各方解决）
    - Linux 常用命令、网络基础知识
    - SQL 数据查询统计
    - 文档编写（用户手册/测试文档）
    - 责任心、主动性、沟通协作、抗压能力
  - **加分项（不参与符合性判定）**：有任意编程语言相关经验（自动化/脚本能力），用于备注候选人水平。

### 判断结论与输出

- **不符合**：逐条说明，直接返回给用户，**不创建文件夹、不保存简历**。输出格式：
  - 结论：不符合
  - 不符合条目（对照 JD 第几条 + 原文 + 简历证据 + 不符合原因）
  - 能力匹配项中证据不足、需补充核验的条目（如有）
  - 说明：如需补充材料（如学历证明、测试项目细节）可提供后重新评估
- **符合**：返回「符合」结论 + 匹配概览（逐条符合/部分符合及依据），然后进入建档模式：创建 `<候选人姓名>/` 文件夹、保存原始简历源文件，再生成「候选人核验信息表」。若按放宽口径通过（非计算机专业 + 测试经验超 2 年），须在匹配概览、匹配检查结果列和核验备注中明确标注「专业为放宽项」。

## 输入处理

- **每次处理简历必须先执行「JD 符合性判断」**：判定不符合时停止处理，不创建文件夹、不保存简历，直接向用户返回不符合原因；只有判定符合后才继续解析、建档。
- 简历可能以纯文本粘贴或文件路径（PDF/Word/Markdown 等）提供。读取并解析出：姓名、工作年限、学历专业、技术栈、项目经历、亮点。
- 用户以附件形式发送简历（PDF/Word/Markdown 等）时：先解析内容用于核验，同时把附件源文件原样复制保存到产物目录（见「产物与目录结构」），便于留档核验。
- 必须尽量从简历文件名、简历正文、用户补充信息中提取并回填「候选人关键核验信息」。明确包含的信息直接填入；没有明确证据的信息对应位置留空即可，不要猜，也不要写「待确认」「（留空）」等占位文字。生成完成后若有缺失项，在最终回复中逐项列出并提示用户补充。
- 生成时自动填写「固定岗位 JD 匹配检查」：证据列填入从简历提取的对应内容，结果列勾选匹配度（满足/部分/不满足、强/中/弱）；简历中无对应信息时证据列与结果列留空、不勾选，现场再核验。
- 固定 JD 是默认岗位要求。若用户同时提供岗位 JD：除非用户明确说替换固定 JD，否则以固定 JD 为主、用户 JD 为补充。
- 简历中姓名缺失、不明确，或一个文档含多名候选人时，先询问用户确认。

## 候选人关键核验信息

在《候选人核验信息表.md》中，候选人关键核验信息必须以 **text 代码块**（```text ... ```）逐行列出，**首行为姓名与手机号**，其后为以下 9 项，方便整段复制；**不要使用表格，不要设置备注列**。姓名、手机号从简历或用户补充信息中提取；若求职者简历中或用户发来的信息中明确包含某项信息，直接把对应信息写到冒号后；若没有明确包含，冒号后留空，不要写「待确认」「（留空）」等占位文字。不要根据城市、籍贯、电话归属地等间接信息强行推断。

## 产物与目录结构

**仅当 JD 符合性判断为「符合」时**，才在当前工作区创建文件夹 `<候选人姓名>/` 并保存简历；**判定不符合时禁止创建文件夹、禁止保存简历**，直接向用户返回不符合原因。符合时文件夹包含：

1. `简历.md` — 原始简历内容转录（保留原文，便于对照）
2. `简历源文件`（可选）— 用户以附件形式发送的简历源文件（PDF/Word/Markdown 等），原样复制保存一份并保留原始文件名；纯文本粘贴、无源文件时省略
3. `候选人核验信息表.md` — 核验信息文档：候选人关键核验信息（9 项，代码块文档格式）+ 固定 JD 匹配检查（结构见 [assets/候选人核验信息表模板.md](assets/候选人核验信息表模板.md)）

从 assets/ 复制模板后填充。

## 候选人核验信息表.md 结构

1. **头部信息**：候选人、应聘岗位、建档日期、判断依据、JD 符合性结论
2. **候选人关键核验信息**：代码块首行为姓名与手机号，其后 9 项（目前所在地、长期青岛工作接受程度、籍贯、收到 offer 最快到岗时间、当前状态、期望薪资、是否接受外包、海信/海尔投递面试情况、全日制本科教育部学历验证报告验证码）；以 text 代码块逐行呈现，便于复制；明确信息直接回填到冒号后，缺失项留空，不设备注列
3. **固定 JD 匹配检查**：根据简历证据自动填入匹配结果（证据列 + 结果列勾选），无对应信息时留空
4. **核验备注区**（可选）：其他需要现场确认的信息（如期望薪资与岗位区间差异、能力待核验点）

## 重名与覆盖

- 若 `<候选人姓名>/` 文件夹已存在：重新生成全部内容并覆盖旧文件（保留最新一份）。
- 用户要求保留历史版本时，改为按时间戳归档（如 `姓名_2026-08-13/`）。
- 覆盖前确认候选人与文件夹名一致，避免误覆盖不同候选人。

## 不确定时询问用户

以下情况先确认再继续：

- 简历中姓名缺失/不明确
- 同一文档含多名候选人
- JD 与简历技术栈明显冲突（以哪个为准）
- 用户指定了特殊建档要求而简历无法支撑
